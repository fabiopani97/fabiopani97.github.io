Projet 06 — Automatisation PowerShell AD

Scripts d'automatisation pour la gestion quotidienne des comptes Active Directory

PowerShell Active Directory RSAT Automatisation

Contexte

Dans le cadre de ma formation Technicien Systèmes & Réseaux, ce projet vise à automatiser deux tâches récurrentes du support N1/N2 sur un annuaire Active Directory : le déblocage de comptes utilisateurs et la création de comptes à partir d'un export RH.

Script 1 — Déverrouillage & réinitialisation de mot de passe

Automatise le déverrouillage d'un compte bloqué et la réinitialisation de son mot de passe (saisie sécurisée via SecureString). Chaque action est journalisée et les erreurs (compte introuvable, droits insuffisants, mot de passe non conforme) sont interceptées sans interrompre le script.

$NouveauMDP = Read-Host "Entrez le nouveau mot de passe" -AsSecureString
try {
    Set-ADAccountPassword -Identity $Identifiant -Reset -NewPassword $NouveauMDP -ErrorAction Stop
    Write-Log -Identifiant $Identifiant -Message "Reinitialisation MDP : SUCCES"
} catch {
    Write-Log -Identifiant $Identifiant -Message "Reinitialisation MDP : ECHEC - $PSItem"
}

Script 2 — Création de comptes AD depuis un CSV RH

Automatise la création quotidienne de comptes utilisateurs à partir d'un fichier CSV simulant un export RH. Le script vérifie l'existence de chaque compte avant création (idempotence), place l'utilisateur dans la bonne OU, l'ajoute au groupe de sécurité correspondant, et journalise chaque action sans interrompre le traitement des autres lignes en cas d'erreur.

foreach ($Ligne in $ListeUtilisateurs) {
    try { Get-ADUser -Identity $Ligne.SamAccountName -ErrorAction Stop; $ExisteDeja = $true }
    catch { $ExisteDeja = $false }
    if ($ExisteDeja) { Write-Log ... ; continue }
    $OUCible = Get-ADOrganizationalUnit -Filter "Name -eq '$($Ligne.OU)'"
    New-ADUser -Path $OUCible.DistinguishedName -AccountPassword $MotDePasse ...
    Add-ADGroupMember -Identity $Ligne.Group -Members $Ligne.SamAccountName
}

Le script est conçu pour être planifié via le Planificateur de tâches Windows, exécuté par un compte de service disposant de droits délégués (principe du moindre privilège), et non de droits d'administration globaux.

Sécurité & bonnes pratiques

  • Les mots de passe ne sont jamais écrits en clair dans les logs (conversion en SecureString)
  • Gestion d'erreurs try/catch sur chaque opération à risque, sans interruption du traitement global
  • Journalisation complète (date, identifiant, action, résultat) pour la traçabilité
  • Principe du moindre privilège pour le compte d'exécution
